# 模型接入与工具执行（v0.2）

## 运行方式

任务显式选择 `demo` 或 `model`。默认 demo 完全离线且不产生模型费用。model 使用服务端环境变量中的工具调用模型；未配置时 API 返回 503，不自动伪装成模型模式。

需要一个支持 Chat Completions 风格 `tools/tool_calls` 的接口：

- `ONTOLOGY_MODEL_URL`：完整接口地址，以 `/chat/completions` 结尾。
- `ONTOLOGY_MODEL_NAME`：服务方实际提供的模型名称。
- `ONTOLOGY_MODEL_KEY`：服务端密钥，不写入源码、任务参数或浏览器。
- `ONTOLOGY_MODEL_MAX_OUTPUT_TOKENS`：可选，每次请求的输出预算，默认 4096，允许 256～32768；实际支持的上限由模型服务决定。提高预算可能增加费用和耗时。

可以复制 `.env.example` 为 `.env`。Docker Compose 会读取这些配置；本地运行请在 shell 或进程管理器中设置同名环境变量后重启服务。HTTP 仅允许本机地址用于开发测试；远程地址必须 HTTPS。不跟随服务重定向。

页面的“参数已配置”只表示本地校验通过，不等于已连接或已通过真实服务验收。当前没有用户提供的模型凭据，本次只完成协议模拟测试，未消耗任何真实模型额度。

配置后，模型模式会把用户任务与本次检索资料发给选定服务。当前身份仍是固定演示项目，不可直接部署为多用户公网系统。

## 模块契约

| 模块 | 职责 |
|---|---|
| `model.py` | 服务配置校验、HTTP 请求、响应结构校验、大小／超时限制、错误脱敏 |
| `tools.py` | 工具注册、参数模式、项目过滤、只读查询和可信代码样例 |
| `agent.py` | 模型循环、工具响应关联、证据引用校验、停止条件、草稿交付 |
| `engine.py` | 数据库任务领取、租约续期、持有者校验、逐调用持久化与恢复 |

模型工具：`search_documents`、`read_document`、`get_object`、`get_relations`、`inspect_runtime`、`inspect_code_example`（仅编码任务）、`submit_answer`。

没有任意 URL、SQL、文件路径、shell 或发布工具。`inspect_runtime` 仍是模拟业务连接器；`inspect_code_example` 只执行可信内置样例，不执行模型生成的代码。

## 正确性边界

模型返回的工具参数必须经过 Pydantic 校验；不认识的工具和多余字段会被拒绝。工具结果生成本次证据 ID；提交草稿只能引用本次成功查询产生的 ID。引用 ID 有效不能证明所有自然语言陈述都被来源支持，页面明确标为未审核草稿。

是否满足“已修复”的规则由 `inspect_runtime` 返回的确定性结果决定，不接受模型自行设置。未取得运行证据时，客诉／运维任务不会被标为确认修复。需求与编码任务保持草稿状态；任何输出都不会自动发送、合并或发布。

## 限额与失败

- 每任务最多 6 次模型请求、12 次工具调用；连续工具错误 3 次停止。
- 模型单次输出默认上限 4096 tokens，可通过 `ONTOLOGY_MODEL_MAX_OUTPUT_TOKENS` 调整；上下文序列化上限 48000 字符；单响应上限 512 KB；默认请求超时 20 秒。
- 每轮检查任务时间，默认 180 秒预算；不自动重试模型 HTTP 请求。限额构成调用边界，不是准确的货币预算。
- 达到轮数或工具限制返回 `partial`，保留证据。模型请求失败为 `failed`，已写入的调用和证据仍可查看。
- 不保存供应商原始错误正文、密钥或模型内部思维文本。调用记录保存允许工具参数、结果及简要状态。
- 任务恢复产生新 attempt，旧记录保留；接口默认展示当前 attempt。模型推理会从头重新开始，可能增加费用，不承诺逐 token 恢复。最多 3 次领取尝试。
- 每步续租并校验 worker_token，过期 Worker 不能覆盖新持有者。当前仍为单进程后台线程；生产应独立 Worker 并完善预算与停机策略。

## 协议参考与后续

工具调用消息结构参考 [Function calling](https://platform.openai.com/docs/guides/function-calling)。当前使用 Chat Completions 兼容协议，不承诺适配所有供应商或仅支持其他协议的模型；需要对实际服务验证工具 schema 和参数兼容性。

下一步接入真实业务系统、企业身份与审批；完善语义支持评测和模型输出审查；实现安全代码执行器与受控写动作。更换模型不应修改文档、语义数据和证据接口。
