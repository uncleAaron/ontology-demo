# Ontology Workbench

一个可以本地运行的业务 Agent 架构演示工程。使用 **FastAPI + SQLite + 原生 JavaScript/SVG**，将文档、本体、实例图谱和任务证据接到真实数据库与 API，而不是只在页面切换预设文案。

> **当前是开发演示，不是已接入企业系统的生产 Agent。** 业务状态仍由模拟连接器给出；可选择无需模型的确定性演示，或配置服务端模型后启用工具调用。企业身份系统尚未接入，模型输出是待审核草稿。没有配置模型时不宣称自然语言已被理解。

## 快速启动

需要 Python 3.12+。Node.js 20+ 仅用于构建时检查前端脚本。

```bash
git clone https://github.com/uncleAaron/ontology-demo.git
cd ontology-demo
make setup
make run
```

打开 http://127.0.0.1:8000 ，API 文档位于 http://127.0.0.1:8000/docs 。

不使用 Make 时：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

数据默认保存在 `data/demo.sqlite3`，通过 `ONTOLOGY_DB` 指定其他路径。重启服务不会清空导入资料、候选关系、任务或证据。需要空白演示环境时，请使用一个新的数据库路径。

也提供 `docker compose up --build` 配置，默认仅绑定本机 8000 端口；当前执行环境没有 Docker，此路径尚未在本环境验证。

## 建议体验顺序

1. **文档知识库**：阅读三份种子资料，也可导入 Markdown/TXT；支持标题和正文子串搜索。
2. **本体模型图**：查看对象类型和允许的关系，点击连线检查类型约束。
3. **实例关系图**：以客诉或服务为中心展开邻居，切换确认／候选／失效状态；点击关系阅读来源。
4. **路径查询**：选择 `CS-1042` 到 `abc123`，观察工单、功能、服务、版本、提交之间的有向路径。
5. **Agent 任务**：对比尚未发布、未验证、已验证、来源冲突、证据过期五种场景。
6. **任务证据图**：从交付结果打开本次实际保存的证据，不把当前图谱重新拼装成历史证据。
7. **编码与测试**：运行内置回调样例，真实执行修改前后测试，查看 diff。修改前重试用例失败，修改后三个测试通过。

## 知识自维护体验

建议先运行一个任务，随后打开“文档知识库”中的修复说明：

1. 展开“登记来源新版本”，修改正文并填写原因。提交后来源进入待复核，Agent 检索和依赖旧来源的确认关系立即停止使用。
2. 查看内容差异、不可变版本历史、直接关系与引用任务。批准只发布原文；有依据时逐条确认关系并绑定新修订。
3. 拒绝修订不会恢复旧版；撤回会继续阻断且当前不提供恢复入口。已完成任务保留原始记录并展示来源变化警告。
4. 固定模板任务绑定最初种子资料，资料变化后会交付“需重新取证”，不能把新版本自动用于旧模板。模型模式可读取审核后的新原文，但仍须配置实际模型服务。

首次升级自动迁移 schema v2→v3；建议先备份 SQLite 文件。新资料以演示维护身份直接导入并生效，后续更新走复核流程。没有企业鉴权、自动抽取、定时巡检或多源支持裁定，不将本轮称为完整自主维护系统。

## 已实现与明确边界

| 能力 | 已实现 | 后续生产能力 |
|---|---|---|
| 数据层 | SQLite WAL、外键、初始化、持久化任务 | 企业数据库适配、迁移和备份策略 |
| 文档 | 文本导入、子串检索、不可变修订、人工批准／拒绝、撤回及查询阻断 | 企业审核身份、文件解析、混合检索、自动来源同步 |
| 本体与图谱 | 类型及关系定义、实例、来源、状态、局部图、路径、类型校验候选写入 | 模型发布与兼容迁移、持续同步、多来源治理 |
| 图工作台 | 三种视图、展开、筛选、来源详情、缩放平移、拖动、键盘列表、截断提示 | 时间对比、复杂影响分析、布局配置及授权导出 |
| 知识维护 | 文档级关系血缘、逐条复核、差异与审计、引用任务影响、版本冲突保护 | 片段级血缘、多源冲突、候选自动抽取、巡检及通用回滚 |
| 任务 | 数据库领取、持有者令牌、逐步续租、后台执行、attempt记录、知识有效性复核和证据快照 | 独立 Worker 部署、取消、人工暂停恢复、货币预算及幂等外部动作 |
| 四类能力 | 演示交付、可配置模型工具调用、编码样例补丁与真实样例测试 | 实际模型服务验收、实际仓库接入、真实业务连接器 |
| 访问控制 | 固定演示项目在服务端过滤；隐藏对象不能用于路径 | 企业登录、角色、对象与动作权限、审批 |
| 验证 | 自动化 API、规则、图查询、恢复和样例测试 | 企业数据质量验收、性能测试及生产安全审核 |

SQLite 是本地可复现的关系型存储选择，不表示已确定生产数据库。图渲染使用 SVG，不依赖图数据库。当前图谱种子时点固定在 2026-09-30；实时连接器返回值均标为模拟。没有读取或修改任何真实客户数据、业务部署或外部代码仓库。

## 工程结构

```text
app/db.py       表结构、种子数据、关系类型约束校验
app/graph.py    授权项目范围内的局部图与有向路径
app/knowledge.py 资料版本、来源血缘、复核发布、撤回与任务保护
app/engine.py   持久化任务领取、确定性场景、内置代码测试
app/main.py     API、演示身份边界、后台 Worker 生命周期
app/model.py    可配置模型接口与响应校验
app/tools.py    只读工具注册、参数和范围校验
app/agent.py    有上限的工具调用循环与草稿交付
static/        中文工作台、SVG 图与任务交互
scripts/       构建检查与源码归档
tests/        核心行为测试
 docs/         架构、特性基线与实施路线
```

## 可选模型模式

参见 [模型接入说明](docs/model-integration.md)，在服务端设置 `ONTOLOGY_MODEL_URL`、`ONTOLOGY_MODEL_NAME`、`ONTOLOGY_MODEL_KEY` 后重启。页面显式选择“模型辅助”。默认仍为离线演示，配置状态不等于远程服务已验证。模型模式会向指定服务发送任务及所查资料，业务连接器仍为模拟。

```bash

```

构建检查 Python 编译与 JavaScript 语法，生成 `dist/ontology-demo.tar.gz` 源码分发包。前端为静态资源，无前端打包依赖。仓库不提交虚拟环境、数据库、密钥或生成的归档。

## 运行边界

- 默认仅监听 localhost。固定演示身份不是身份认证，不能直接暴露到公网或作为企业权限系统使用。
- 所有网页内容使用转义渲染；文档中的命令不会被执行。API 对关系端点类型和项目范围做校验。
- 编码测试只执行工程内置可信代码，使用临时工作目录和超时限制；**这不是可执行任意不可信代码的安全沙箱**，不接受任意 shell 命令。
- 不提供外部写操作，因此不会因任务重试发送消息、发布或回滚。增加外部动作前必须实现幂等键、结果核对和执行前审批。
- 任务输入和模拟结果保存在本地数据库；使用时不要提交真实敏感信息。
